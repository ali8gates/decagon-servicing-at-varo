# Why we did this

## The problem with the old bot

Amazon Lex worked like a phone tree in text form. Every question and answer had to be scripted by hand. In the April 2026 training, the team summed it up this way: Lex is fixed, meaning you have to script everything out, while Decagon works in natural language (Decagon company training, Apr 3, 2026).

In practice this meant:

* Customers who phrased things differently got stuck.
* New topics needed new scripts, which took engineering time.
* Some requests, such as closing an account, were not supported at all (Decagon company training, Apr 3, 2026).
* Many chats ended up with a human agent, which costs more and makes customers wait.

## What we wanted

1. **Fewer chats needing a person**, so agents can focus on hard cases.
2. **A better customer experience**, with answers in plain language at any hour.
3. **Growth without matching cost growth**, since Decagon handles routine volume.
4. **Readiness for the busy season**, January to March (Customer service partner next steps, Nov 12, 2025).
5. **Ownership**, so Varo controls its data, content, and workflows and can build on them later (Customer service partner next steps, Nov 12, 2025).

## Why a support assistant and not a better script

A script can only answer the questions someone predicted. A support assistant can understand a new wording, pick the right help article, ask a follow-up question, and, once connected to Varo's systems, check a balance or start a card action. That is the difference between a menu and a conversation.
